# PyTorch GPU

market_data - Получение данных с bybit
orderbook - логика торгового стакана
storage - хранение данных
features - расчет признаков
visualization - отображение данных

orderbook (Ядро стакана)Это самое сердце вашего проекта. Здесь находится структура данных самого стакана и логика его изменения. Никакой сетевой логики или графики здесь быть не должно.
model.py / orderbook.py — объект стакана (обычно на базе BTreeMap в Rust или кастомных двусвязных списков/деревьев в Python, например blist). Содержит уровни Bid/Ask.engine.py — матчинговый движок (Matching Engine) или процессор лимитных ордеров, если стакан локальный. Логика сведения заявок.types.py — базовые типы данных: Order, Trade, PriceLevel, Side (Buy/Sell).

market_data (Потоковые данные)Отвечает за получение, первичную обработку (парсинг) и передачу сырых данных с биржи внутрь системы.
connectors/ — подпапка с модулями подключения к биржам (например, binance.py, bybit.py). Внутри — логика WebSocket и REST API клиентов.parser.py — превращает JSON-ответы от биржи в стандартизированные объекты вашей системы (те самые Order или Trade из папки orderbook).stream.py — менеджер потока данных, который управляет переподключениями (reconnects) и подписками на топики (@depth, @ticker).

features (Вычисление метрик и сигналов)Здесь рассчитывается производные метрики на основе состояния стакана и потока сделок. Эти данные затем идут в торговых роботов или на графики.
imb.py (Order Book Imbalance) — расчет дисбаланса объемов между Bid и Ask на разных уровнях глубины.
spread.py — вычисление ширины спреда (моментального, среднего, взвешенного по объему).
micro_price.py — расчет микро-цены (взвешенной по объемам топ-уровней стакана).
vwap.py / twap.py — средневзвешенные цены по объемам или времени на основе ленты сделок (Trades).
flow.py (Order Flow Toxicity) — метрики токсичности потока ордеров (например, VPIN).

storage (База данных и логирование)Отвечает за сохранение исторических данных для последующего бэктеста стратегий или анализа ошибок.
writer.py — логика быстрой записи snapshot-ов (снимков стакана) и delta-обновлений.
reader.py — интерфейс для чтения исторических данных для бэктестера.
db_client.py — коннекторы к базам данных (для тиковых данных и стаканов обычно используют ClickHouse, TimeScaleDB, HDF5-файлы или QuestDB).

visualization (Интерфейс и графики)Отвечает за отображение состояния стакана и графиков метрик пользователю. Модули из этой папки только читают данные из orderbook и features, но никогда не меняют их состояние.
dashboard.py — главное приложение (например, на PyQt, CustomTkinter, Streamlit или Dash).components/ — отдельные виджеты: таблица самого стакана (L2/L3), лента сделок (Time & Sales), график глубины (Depth Chart).
charts.py — отрисовка реалтайм-графиков для вычисленных фичей (например, график изменения спреда или дисбаланса).


Эти модули лучше связать либо через событийную модель (Event-driven) или через очередь сообщений (asyncio.Queue в Python).
Поток данных должен выглядеть так:
market_data (поймал вебсокет) ➡️ orderbook (обновил состояние стакана) ➡️ features (пересчитал метрики) ➡️ visualization (отрисовал) + storage (записал в лог).
